# Issue #630 — VoiceView: bars and ring as avatars

**Status:** In Progress

## Plan

Started as "VoiceView's bars and ring become avatars". After the first round the owner asked why there were several things for the same job ("min tanke med avatar var att visualisera ljud input/output") and decided: **AvatarView is the one visual for a voice.** VoiceView, its orb, its canvas face and the `VoiceVisual`/`VoiceVisualView` contracts go; bars and ring stay as built-in avatars; the Showcase draws every voice page through AvatarView.

- **Format:** spine2d parameters per band, `inputBand0`–`inputBand23` and `outputBand0`–`outputBand23`, so a vector avatar draws a spectrum. Vector rather than SkSL: a shader renders through a 112 px buffer on CPU canvases (Android, Windows), which blurs bars.
- **Built in:** `bars.spineavatar` and `ring.spineavatar`, generated by a script in the repository, packed with the spine-avatar tool into `samples/Avatars` and embedded in Controls.Avatar; `AvatarSource.BuiltIn(name)`, and in XAML `Source="bars"`.
- **Packages:** `Plugin.Maui.Spine.Controls.Voice` (and the briefly merged `Controls.Avatar.Voice`) removed; `VoiceAvatarDriver` moves into Controls.Avatar, which references Spine.Voice. Neither package had shipped (v0.1.9 predates both).

## Decisions

- **The voice is the avatar's, the choice the server's.** The package names its voice, the app asks, and the server only grants voices the feature lists, so a client cannot pick a voice the owner has not offered; an unknown one falls back to the feature's own rather than failing the connection.

- **One visual for a voice: AvatarView** (the owner, 2026-10-19): the orb is removed, not converted; the canvas face is retired (Nova and Puff do it better); the canvas plug-in contracts go (a look of one's own is a `.spineavatar`); the Showcase keeps one path.
- **No `Kind` property.** The owner suggested a kind setting; `Source` already picks the avatar, so a second property would be two ways to say the same thing. A built-in avatar is a source by name instead: `Source="bars"`.
- **The microphone in `accent`.** VoiceView's `InputColor` defaulted to the app's accent; the `accent` slot gives the same without a new property, and `AccentColor` overrides it. The answer is the `output` slot (`SetThemeColor`).
- **The driver in Controls.Avatar.** Spine.Voice is light (Common, Speech, the AI abstractions), and a separate package for one class would bring back the split the owner wanted gone.
- **Vector, not SkSL.** A shader is drawn on the CPU into a buffer of at most 112 px and scaled up (Android, Windows), which blurs bars; spine2d paths stay sharp everywhere.
- **One path node per band**, rotated to point up, down or outward and scaled along it from its inner end: a group plus a shape per band gave the ring 198 nodes, over the format's 128.
- **An empty first root node** in both packages: the scheduler's springs (squash, tilt, lift) move the first root, and a spectrum that wobbles reads as wrong.
- **Avatars keep their aspect** (`fit: contain`): in a very wide, short view the bars are smaller than a canvas that filled any rectangle.
- Posters are rendered under Reduce Motion by the tool, so bars' poster is its bell of bars.
