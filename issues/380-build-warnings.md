# Issue #380 — Build warnings

**GitHub:** https://github.com/jonatansoderberg/Maui.Spine/issues/380
**Branch:** issue/380-build-warnings
**Status:** In Progress

## Plan

The CI build of `Spine.Packages.slnf` lists about 320 distinct warnings, and the sample adds a few more. Fix them where they are, without blanket `NoWarn` and without changing behaviour:

1. **CS1591 in `SpineIcons`** (219): the constants are generated by `.claude/skills/spine-symbol/symbols.py`; give each generated constant a short `<summary>` there and regenerate.
2. **Doc comments** (CS1572/1573/1574/0419/1591): add the missing `<param>` tags, move constructor params off the class, point crefs at members that exist, disambiguate overloads.
3. **Nullability** (CS8602/8604/8765), mostly Android bindings annotated nullable: pattern matching or `?.` where the value can be missing, a `!` only where the Java API is `@NonNull`, and splitting fluent AndroidX builder chains into statements on the (non-null) builder.
4. **Obsolete APIs** (CS0618/0672, CA1422): use the replacement where there is one; otherwise a targeted `#pragma` with the reason.
5. **Platform guards** (CA1416): `OperatingSystem.Is…VersionAtLeast` or `[SupportedOSPlatform]`.
6. **NU1608** in PushNotifications: lift the AndroidX Lifecycle packages MAUI brings to the release Firebase needs.
7. **Sample** warnings (CS0109, CS1574).

Out of scope, left for the parallel header-bar rewrite that is replacing these files: `PagePresenter.cs`, `NavigationRegion.cs`, `HeaderBarConstants.cs`, `SpineOptions.cs`, and the sample's `MainPage.*`.

## Changes

- `symbols.py` writes `/// <summary>The <c>X.svg</c> icon.</summary>` above every constant (and now finds the class body by its brace, so it is idempotent with the summaries in place); `SpineIcons.cs` regenerated. The `/spine-symbol` skill mentions the summary for hand edits.
- Doc comments: `<param name="cancellationToken">` on `IWidgetService.StorePackageAssetAsync` and `PackageFiles.CachedPathAsync`; `target`/`build`/`cancellationToken` on `PushSender.DispatchAsync`; `PushNotificationService`'s `<param>` tags moved from the class to its constructor; crefs fixed in `WidgetNode.Pending` (`WidgetNodeStyling.Pending{T}(T)`), `IThemeService` (`Element.HandlerChanged`), `SpineTabbedHostPage.SwitchToAsync` and three `UseEmbeddedSvgImages` references (now the parameterless overload); `<inheritdoc/>` on `SvgImageSourceBehavior.OnAttachedTo`/`OnDetachingFrom`.
- `SpineApplication.Windows.cs`: removed the public `User32` class, which nothing referenced (its 11 undocumented members were the Windows CS1591s).
- `AnimatedLabel`: dropped the obsolete `SKPaint.FilterQuality`; the draw call already passes `SKSamplingOptions`, which is what decides the filtering.
- `SvgIcon`: `DrawPicture(picture, in matrix)` instead of `ref` (CS9191).
- Android, `Plugin.Maui.Spine`: `IMenu.None` instead of the obsolete `Menu.None`; `ContextCompat.GetColorStateList` for the tap highlight (API 21+, where `Context.GetColorStateList` needs 23); `RoleDelegate.OnInitializeAccessibilityNodeInfo` takes nullable parameters like the base and returns when there is no node; `?.` on `WindowCompat.GetInsetsController` (C# 14 null-conditional assignment); pattern for `Paint.GetFontMetrics()`; `!` on `PopupMenu.Menu` and `WindowInsetsCompat.GetInsets` (both `@NonNull`), which also drops the dead `Insets.None` fallback.
- `HeaderBarView.UpdatePresentationSizes` returns when the content is not the grid instead of dereferencing a possible null.
- Apple: the glass part of `ApplyGlass` moved to `ApplyGlassConfiguration`, marked `[SupportedOSPlatform("ios26.0")]`/`("maccatalyst26.0")` along with `BuildConfiguration`, and called behind the existing iOS 26 check; `ContentEdgeInsets` in `MenuExtensions.Apple` kept behind a `#pragma` (it is what MAUI lays out a button without a configuration with).
- PushNotifications, Android: fluent AndroidX builder chains (`NotificationCompat.Builder`, `NotificationChannelCompat.Builder`, `BigPictureStyle`, `RemoteInput.Builder`) split into statements on the builder; `NotificationManagerCompat.From(...)` null-checked; `PendingIntentFlags.Immutable` only from API 23, as the Widgets package already does; `FirebaseMessaging.GetToken` and `OnNewToken` behind a `#pragma`.
- `OpenSettingsAsync` on Android opens the app's notification settings from API 26 (unchanged) and the app's details page below that.
- `Directory.Packages.props` / PushNotifications csproj: `Xamarin.AndroidX.Lifecycle.LiveData` and `Lifecycle.Process` 2.11.0.1 referenced next to `LiveData.Core`, which removes the three NU1608s.
- Sample: `ContextItem.Title` without the needless `new` (CS0109); `ToggleRow`'s cref points at `ToggleListSheetViewModel.Log`.

## Decisions

- **`SpineIcons` summaries are generated**, not suppressed: the file is regenerated by `/spine-symbol`, so the fix belongs in `symbols.py`. The text is deliberately plain (the file name); the class summary already explains how they are used.
- **`!` only on `@NonNull` Java APIs** (`PopupMenu.getMenu`, `WindowInsetsCompat.getInsets`). Where a result could in principle be missing, or the call is a void side effect (`NotificationManagerCompat.From(...)?.Cancel`), a pattern or `?.` is used instead. Fluent AndroidX builders return `this` but are bound as nullable, so the chains became statements rather than a `!` after every call.
- **Firebase `GetToken`/`OnNewToken`**: the Xamarin binding marks both obsolete ("deprecated") with no replacement in the binding; they are still the only way to read and learn about the FCM token, so they stay with a targeted `#pragma` and the reason.
- **`OpenSettingsAsync` below API 26** now opens the app's details page. `ACTION_APP_NOTIFICATION_SETTINGS` and `EXTRA_APP_PACKAGE` are public from API 26; before this change API 21–25 got an action and extra that are not public there, which the settings app may not honour. From 26 up nothing changes.
- **`PendingIntentFlags.Immutable` below API 23** is left off, matching `SpineAppWidget`/`SpineBackgroundReceiver`; the flag did not exist there, so the system ignored it anyway.
- **`User32` removed rather than documented**: it was public by accident (Windows-only P/Invoke helpers in `Plugin.Maui.Spine.Core`) and unused. Strictly a public API removal, on Windows only.
- **NU1608**: MAUI 10.0.50 brings `Lifecycle.LiveData`/`Process` 2.9.2.1, which pin `LiveData.Core`/`Runtime` below 2.9.3, while Firebase's `Fragment` 1.9.0 needs 2.11.0.1. Referencing LiveData and Process 2.11.0.1 as well lines the family up; the sample builds for Android (D8 included) with no duplicate classes.
